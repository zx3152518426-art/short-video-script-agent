# 方案与取舍

模型每轮拿到用户要求和之前的工具结果，返回一个动作及参数。程序执行后，把返回值交给下一轮模型。模型根据返回结果决定补查、改稿、重试或结束。

可选动作有三个：

| 动作 | 做什么 | 返回什么 |
| --- | --- | --- |
| `search` | 按产品名、关键词或别名查资料 | 产品 ID、事实 ID、原文、品牌用语表 |
| `check_script` | 接收模型安排的分镜，生成旁白并检查 | 每镜时长、引用、总时长、风险项 |
| `finish` | 完成、追问或停止 | 状态、说明、待补充项 |

模型先选事实、开场和收尾，工具再把事实 ID 转成原文。这样，口播内容可以逐句回查。每次 `check_script` 都保存一份版本；模型能看到超出了几秒、哪句触发规则，再决定删什么。

## 时长计算

按旁白中的汉字数和英文词数估算：每秒 4 个单位，每镜加 0.6 秒停顿，最低 2 秒。参数放在规则文件，修改语速就能观察结果变化。最终剪辑时再按实际配音微调。

## 完成状态怎么判断

`completed` 必须指向最新且检查通过的 `script_id`。漏填关键输入、跳过检查、使用旧版本 ID，都会把错误返回模型。执行达到 8 步时，程序返回未完成，并保留已经产生的稿件。

工具错误会进入下一轮观察，模型自己决定重试或停止；模型接口失败则结束本次执行。

## 技术选择

使用 Python 标准库实现循环、JSON 读写和本地工具。`src/agent.py` 负责动作分发和状态流转，`src/tools.py` 负责检索与检查。

Codex CLI 返回模型选择的动作，每次用 JSON Schema 限定返回结构。本地工具由 Python 执行。另留了兼容 Chat Completions 的接入类，切换接口不需要改业务工具。

检索按产品名称、关键词和别名匹配资料，返回产品 ID、事实 ID 和原文。模型可以根据空结果换词补查，也可以直接引用已找到的事实。
