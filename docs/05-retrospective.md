# 复盘

最费心的是“什么时候可以说完成”。最初只要曾经有一个版本通过，就容易忽略后面提交的新稿。现在每次检查新稿都会清掉当前通过状态，结束时还要核对版本 ID。这样一来，最终分镜稿和检查结果对应的是同一版。

另一个取舍是旁白自由度。完全放开生成，写起来更顺，但核查每个功能点会变复杂。这次先把产品事实固定成可引用的原文，让模型安排镜头、选择重点、按时长删减。读测试记录时，很容易看到它到底删掉了哪条事实。

下一步会优先做两件事：增加“保留这句卖点”的约束，避免压缩时删掉用户最看重的内容；接入一次实际配音，把字数估时和真实音频时长作比较。界面可以之后再补，先让脚本在改稿过程中保持可用。
