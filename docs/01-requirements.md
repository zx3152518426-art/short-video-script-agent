# 要解决的问题

运营拿到一份产品资料，要给刚开始做口播的人写一条字幕功能演示视频。要求发抖音，控制在指定时长内。写完以后，还要确认旁白里的功能确实有资料支持。

最容易反复修改的是两件事：为了讲完整，稿子越写越长；为了写得有吸引力，顺手加上了资料里没有的效果。这个项目把查素材、写分镜、检查和改稿放在同一次任务中。

## 输入与输出

输入包括主题、受众、平台、目标秒数和风格。已有初稿也能一起传入，Agent 先检查初稿，再决定怎么改。

输出是一份带标题、画面安排、旁白、字幕、每镜时长和素材引用的 Markdown 分镜稿。JSON 文件额外保留每次修改、风险项和任务状态。

状态分为三种：完成、需要补充信息、未完成。缺少目标时长会问用户；查不到素材会补查或请用户提供；检查多次仍不能满足时长时，会留下当前稿和具体问题。

## 验收

| 场景 | 应看到的结果 |
| --- | --- |
| 资料齐全 | 生成分镜，通过检查后结束 |
| 缺少关键输入 | 指出具体缺项 |
| 没有产品素材 | 改写检索词或请求素材 |
| 工具暂时失败 | 根据错误重试或返回未完成 |
| 初稿超时 | 精简内容，重新估算 |
| 改变素材、语速或规则 | 引用、时长或检查结果随之改变 |

这次保留命令行入口，把时间用于动作选择、异常处理和可复现的记录。视频生成、配音、发布和账号管理不在本次范围。
