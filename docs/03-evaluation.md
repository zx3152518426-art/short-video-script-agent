# 测试与结果

验证环境：Windows、Python 3.12、Codex CLI 0.165.0-alpha.1.2。真实模型为 `gpt-6.1-sol`，运行日期为 2026 年 10 月 29 日。

## 真实模型执行

| 用例 | 预期 | 实际结果 | 记录 |
| --- | --- | --- | --- |
| 正常生成 | 生成且检查通过 | 4 镜，18.65 秒，完成 | [正常生成](../examples/codex/normal/result.json) |
| 缺少时长 | 请求补充 | 1 步结束，询问目标时长 | [缺少信息](../examples/codex/missing_info/result.json) |
| 没有素材 | 补查或请求素材 | 换词补查后仍无结果，请求补充产品资料 | [没有素材](../examples/codex/no_material/result.json) |
| 检查工具失败一次 | 根据错误继续处理 | 读取临时错误，重试检查，最终完成 | [工具失败](../examples/codex/tool_failure/result.json) |
| 初稿超时 | 改稿并重新估算 | 16.85 秒改为 6.35 秒，满足 8 秒要求 | [超时改稿](../examples/codex/over_duration/result.json) |

正常用例的动作是 `search → check_script → finish`。超时用例增加了一次 `check_script`：第二次提交的稿件删掉开场、收尾，以及颜色、位置、预览三方面的介绍，只留下添加字幕和修改文本。工具失败用例则保留已检索的资料，重试原检查。

Trace 每一步包含动作、参数、工具返回和简短依据。可以直接比较两个检查动作的参数，看到修改发生在哪里。

## 离线测试

`tests/` 中的 27 项测试全部通过，覆盖引用原文、未知素材 ID、缺项、错误参数、时长上限、规则检查、工具失败、模型失败、过期版本 ID 和结果导出。还分别替换了素材原文和语速参数，检查输出是否随数据变化。

批量用例放在 [examples/mock](../examples/mock/summary.json)，包含没有素材、规则违规修订和极短时长无法完成。离线模型按固定逻辑返回动作，方便复现错误；真实动作选择看上面的 Codex 记录。

测试命令和完整输出见 [tests.txt](../examples/tests.txt)。

## 已处理的问题与下一步

已修正新版本检查失败后误用旧通过状态的问题，并为跳过检查、引用旧版本、检查工具报错分别增加测试。

后续重点验证三处：文本估时与实际配音的偏差、同义改写的检索命中率，以及标题和画面描述的语义核查。当前对应的实现分别是字词计数、关键词及别名匹配、词表及数字检查。

这次测试使用两份合成产品资料。后续会增加内容更长、存在版本冲突的素材，再观察检索和改稿是否仍然稳定。
